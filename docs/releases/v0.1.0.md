## Migration

None. This is the first release.

## Backend compatibility

Baseline. The backend must:

- invoke the entry points listed above with their current signatures;
- compute `proof_id_hash`, `commitment_hash`, `metadata_hash`, and
  `issuer_id_hash` as 32-byte digests — the contracts treat these as opaque and
  never verify their construction, so a change on the backend side is invisible
  on-chain until proofs stop matching. Vectors are unpublished
  ([#43](https://github.com/veridatum-labs/earnproof-contracts/issues/43));
- submit schema version 1, the only approved version.

## Rollback

Not applicable — there is no previous release.

For future reference: these contracts have no upgrade mechanism, so a rollback
means deploying the previous WASM to a **new** contract ID and re-pointing every
consumer. The old ID keeps running whatever code it was last given, and state
does not travel with the redeployment. Governed migration is
[#12](https://github.com/veridatum-labs/earnproof-contracts/issues/12).

## Containment

`pause()` on `protocol-config` blocks `register_proof`. It deliberately does not
block revocation or issuer status changes, so an operator can contain an
incident without losing the tools needed to resolve it.

Available during a pause: issuer suspension, issuer revocation, issuer address
rotation, proof revocation, and schema deprecation. Every read stays available,
so verification does not go dark.

## Known limitations

Recorded so a consumer does not have to discover them:

- **WASM hashes are not independently reproducible.** There is no pinned
  `stellar` CLI version and no documented rebuild procedure, so the hashes above
  cannot currently be verified against source
  ([#17](https://github.com/veridatum-labs/earnproof-contracts/issues/17)).
- **`proof-registry` emits no events** — see the table above.
- **No typed errors** — panic strings only.
- **Testnet only.** [`SECURITY.md`](../../SECURITY.md) scopes the project to
  Stellar testnet; no mainnet claim is made.
